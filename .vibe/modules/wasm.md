# Module: wasm

**Role:** `cmd/wasm` is the library's WebAssembly entrypoint: thin `syscall/js` glue exposing enough of `engine.Tick`'s simulation loop (see `modules/root.md`) and `round`'s match-flow bookkeeping (see `modules/round.md`) for the `game` app to drive a match, without a Go toolchain of its own. It carries no simulation logic of its own — every real behavior lives in the root `engine` package and `engine/round`, unit-tested independently; this file is JSON (de)serialization, a per-match session registry, and the JS-facing call surface.
**Files:** `cmd/wasm/main.go`, `cmd/wasm/smoke.mjs`
**Exports (JS, not Go):**
- `globalThis.OpenKakutouEngine.newMatch(requestJSON)` — `requestJSON` a JSON string with `programs`/`starting` (indexed `[P1, P2]`; a program is `states` (`.cns`), `scripts` (the character's `.zss` files in load order, each a `character/zss` `Script`), `animations`, `commands`, see `.vibe/decisions/024`), `roundTimer`, `bestOf`, `bounds`, `gravity`, `comboWindow`; returns `{ data: '{"matchId","state","progress","animations"}'|null, error: string|null }`
- `globalThis.OpenKakutouEngine.tick(requestJSON)` — `requestJSON` a JSON string with `matchId`, `inputs` (`[2]input.TickInput`); returns `{ data: '{"state","round","progress","matchOver","matchWinner","animations","sounds","unsupported","skippedCalls"}'|null, error }`
- `globalThis.OpenKakutouEngine.resetRound(requestJSON)` — `requestJSON` a JSON string with `matchId`, `roundTimer`, `starting`; returns `{ data: '{"state","animations"}'|null, error }`
- `animations` (all three above) — a `[2]FighterAnimState` (JSON `animNo`/`animTime`), indexed by `match.Side` like every other per-side array; sourced from the session's own `FighterRuntime.Context.Anim`/`.AnimTime`, additive/response-only (see Design decision below)
- `sounds` (`tick` only) — a `[2][]evaluator.SoundEvent` (JSON `group`/`sample` pairs), indexed by `match.Side` like `animations`; sourced from `engine.TickResult.Sounds`, normalized per side to `[]` (never `null`) via `normalizeSoundEvents`. Unlike `animations`, a discrete per-tick event log, not continuous state -- a skipped `tick` response loses that tick's events for good. Absent from `newMatch`/`resetRound` (no controllers execute during those calls, so there is nothing to report). See `.vibe/decisions/017`.
- `skippedCalls` (`tick` only) — a `[2][]string`, indexed by `match.Side`, each side normalized to `[]` (never `null`); sourced from `engine.TickResult.SkippedCalls`: the `.zss` `call` statements skipped this tick (undefined function, wrong argument or return count). A parallel field of `unsupported` (controller types), additive (decisions 012, 024). Like `sounds`, a per-tick log a skipped response loses.
- `globalThis.OpenKakutouEngine.closeMatch(requestJSON)` — `requestJSON` a JSON string with `matchId`; deletes that session from the registry and returns `{ data: '{}'|null, error }`. Sessions are never pruned on their own — a caller done with a match ID (match ended, page navigated away) is expected to call this or that session's `FighterProgram`/`FighterRuntime` pairs stay resident for the life of the WASM instance.
**Depends on:** `modules/root.md` (`engine.Tick`, `engine.TickConfig`, `engine.NewFighterRuntime`, `engine.FighterProgram`), `modules/round.md` (`round.NewProgress`, `round.ResetRound`, `round.Progress.RecordRoundResult`/`MatchOutcome`), `modules/match.md`, `modules/input.md`, the external `github.com/openkakutou/stage` module (`stage.StageBoundaries`)

**Design decision:** `main.go` is build-tag gated (`//go:build js && wasm`), invisible to a normal host `go build ./...`/`go test ./...`. Every exposed function is wrapped by a shared `guarded` helper: a panic is `recover()`-ed and reported as `{data: null, error: "..."}` instead of tearing down the module, mirroring `character/cmd/wasm`'s own boundary convention. `newMatch` rebuilds each side's `FighterProgram` through `engine.NewFighterProgram(...).WithScripts(scripts)` (via `programRequest.build`, `scripts` being decoded next to the embedded `FighterProgram`) once, before storing it in the session -- `req.Programs` itself came straight from JSON decoding, which only populates the exported `States`/`Animations`/`Commands` fields, never the precomputed animation index (see `.vibe/decisions/013`). Per-match runtime state (`engine.FighterRuntime`, `input.State`, `combat.ComboState`) stays Go-side in a `map[int]*session` keyed by an opaque `matchId` `newMatch` returns — never round-tripped through JSON — because `input.State`'s progress-tracking fields are unexported by design and would silently lose in-flight command-recognition data on every JSON round trip. Only already-JSON-tagged summary data (`match.MatchState`, `round.RoundResult`, `round.Progress`) ever crosses the JS boundary. See `.vibe/decisions/011-tick-orchestration-scope-and-wasm-session-design.md`. `FighterAnimState{AnimNo, AnimTime}` is a response-only type built by the shared `animState` helper — `match.FighterState` (also the request-side `starting` shape) stays untouched, and `AnimNo` (not `Anim`) avoids reading as a duplicate of the sibling `stateNo` field, since the two can diverge (`changeanim`). See `.vibe/decisions/012-wasm-response-only-animation-state.md`. `smoke.mjs` is a Node.js verification harness (loads the built `.wasm` via `wasm_exec.js`, the same way a browser would) — not a `go test` file, since `syscall/js` code cannot run under the plain Go toolchain — and doubles as a minimal JS usage example.
