# Hit pause and get-hit state entry: same tick, no controllers while frozen, defaults on non-literals

**Context:** Backlog item 022. A landed hit must freeze both fighters for the HitDef's pause times and drive the defender into its get-hit state. Compatibility target (MUST): MUGEN 1.0/1.1 and Ikemen GO. Sources used: the MUGEN 1.1 sctrls/triggers docs for names, defaults and numbering; Ikemen GO's bundled `chars/kfm/kfm.cns` (HitDef values) and `data/common1.cns.zss` (get-hit state logic, MIT licensed). No Ikemen GO engine Go source is available locally, so every timing detail below marked *unverified* is a judgment, not a measurement.

**Decision:**
1. **Same-tick entry.** On the tick `combat.ApplyHits` reports a landed hit (after both fighters' own `tickFighter`), the root package (`applyHitReaction`) sets the attacker's `FighterRuntime.HitPause = pausetime[0]` and, on the defender, `Context.GetHit` plus the get-hit state by its current StateDef Type: S 5000, C 5010, A 5020 (entry bookkeeping through the shared `enterState` helper: Time 0, AnimTime 0, Anim = StateDef anim or state number, Ctrl = StateDef ctrl). Physics still runs on the landing tick.
2. **Counters, in order.** At the start of `tickFighter` (after `input.Step`, which keeps running): `frozen = HitPause > 0 || GetHit.HitShakeTime > 0`. A frozen side decrements whichever counters are positive, runs no controllers, does not advance Time/AnimTime, and `Tick` skips its physics (Position/Velocity held). Ticks landing+1 .. landing+N are the N frozen ticks; `HitShakeOver` (`HitShakeTime == 0`) is true on landing+N+1, so 5000 -> 5001 happens on the first tick after the shake. On every unfrozen tick, after the state machine ran, `HitTime` decrements while >= 0 and stops at -1 (`HitOver` = `HitTime < 0`, or no hit taken yet: MUGEN initializes hittime to -1, so `GetHit.Active` is false on the zero value). With ground.hittime = 11, `HitOver` first reads true 12 unfrozen ticks after the shake. *Unverified against Ikemen GO*: whether its decrement happens before or after the state controllers (would shift HitOver by one tick).
3. **hittime selection.** `ground.hittime` for a defender whose StateDef Type is not A, `air.hittime` for type A (stance, not Position/Velocity). *Unverified*: Ikemen may key on grounded physics instead.
4. **Defaults** (MUGEN 1.1 sctrls doc): pausetime 0,0; ground.hittime 0; ground.slidetime 0; air.hittime 20; animtype Light (0); ground.type High (1); air.type = ground.type. Codes: animtype Light 0, Medium 1, Hard 2 (Heavy accepted, as kfm writes it), Back 3, Up 4, DiagUp 5; type None 0, High 1, Low 2, Trip 3.
5. **Expression fallback (documented divergence).** `combat.ParseHitDef` reads only plain integers and known enum names; an expression value (`var(0)`, `5 + 6`) falls back to that parameter's default, independently per value. MUGEN/Ikemen evaluate these expressions; same stance as `parseDamage`. A single-value pausetime keeps the second at its default. Upgrade path: evaluate through `evaluator` in the root package when a real character needs it.
6. **Missing-state fallback.** A defender with no 5000/5010/5020 state, or stance L/U, keeps its current state; freeze and get-hit vars still apply; no error (the state machine's `ChangeState` would error, so the hit path does not use it).
7. **Frozen = no controllers at all.** `ignorehitpause` (controllers that run during hit pause) is deferred to backlog 034. Two-value damage (033) and extra triggers/OR (028) are untouched.
8. **Allocation.** `ParseHitDef` is allocation-free (hand-rolled integer parse; `strconv.Atoi` allocates on its error path), `GetHit` is a pointer-free value struct on `Context`, and `applyHitReaction` measures 0 allocations; a frozen tick costs the pinned 4 (`input.Step`). A landing tick costs 3 more than the same tick without a landed hit; that gap exists with the hit path disabled (hitdetect's events slice and others, pre-existing), not from this decision.
9. **Evaluator.** `HitShakeOver`, `HitOver`, `GetHitVar(hittime|slidetime|hitshaketime|animtype|groundtype|airtype)`; the argument is read as a name, not evaluated (like `Command`); an unknown name is an error. Other GetHitVar names (xvel, fall, ...) are not recorded yet and error.
10. **Fixtures.** `testdata/kfm_hitdef.cns`: real HitDef lines from Ikemen GO's kfm (provenance and license in its header). `testdata/common1_gethit.cns`: get-hit states styled after `common1.cns.zss` (cites the lines followed, lists what was left out). The MUGEN 1.0 `common1.cns` is never copied.

**Rejected alternatives:**
- *Deferred pending-hit applied next tick* -- rejected: the defender would run one tick of controllers (and could change state, or be hit twice) between the hit and its reaction; same-tick entry matches MUGEN.
- *Synthesized `ChangeState` controllers / `statemachine.applyChangeState`* -- rejected: it errors on a missing target state and would run inside the state machine's controller loop; the hit path needs a silent fallback and happens outside any state's controllers.
- *Evaluating HitDef expressions now* -- rejected as out of scope: needs a Context at hit time and per-hit parsing/allocation on the hot path.

**Reason:** Keeps combat free of evaluator imports and statemachine coupling, adds no per-tick allocation, and records every unverified timing so a conformance harness (backlog 030) can settle them against a real engine.

**Correction round 2 (appended):**
- **Stance normalization.** The defender's StateDef type is read as its first character, case-insensitive (`type = s` == `S`); an omitted type line is standing. Documented: MUGEN 1.1 cns doc, StateDef `type`: "If this line is omitted, it assumes the type is S". `U` (unchanged) and `L` keep the missing-state path.
- **Negative pause times.** `combat.ParseHitDef` clamps both `pausetime` values to >= 0, and `HitShakeOver` reads `HitShakeTime <= 0`, so no input can leave a defender shaking forever. MUGEN/Ikemen behavior for a negative pausetime is unverified.
- **Enum names by first letter.** `animtype` (L/M/H/B/U/D -> 0..5; "DiagUp" is D, "Heavy" is H = Hard) and `ground.type`/`air.type` (N/H/L/T -> 0..3) are decided from the first non-space character, case-insensitive; unknown or missing keeps the default. *Unverified against Ikemen GO's source* (none available locally): the MUGEN 1.1 sctrls doc only lists the full words ("light", "medium", "hard", "back", "up", "diagup"; "High", "Low", "Trip", "None") and states no first-letter rule; the rule is a lenient superset that also accepts real characters' "Heavy" and abbreviations.
- **Trade (both land the same tick).** Each fighter gets its own pausetime[0] freeze and its own get-hit state/vars from the other's HitDef; `Tick` applies P1's reaction, then P2's, and neither overwrites the other's counters (pinned by a test). Whether Ikemen GO resolves a trade in the same order, or lets one hit win, is unverified.
- **Evaluator names are lower-cased once**, at parse time, so evaluating `HitShakeOver`, `GetHitVar(HitTime)` etc. allocates nothing (tested); error messages quote the lower-cased name.
