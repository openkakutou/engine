# WebAssembly entrypoint

`cmd/wasm` builds the library into a WebAssembly module a browser (or any
JS host) can load directly — no local Go toolchain needed. It is thin glue
only: all real simulation logic lives in the root `engine` package and its
sub-packages (see [docs/architecture.md](architecture.md)), unit-tested
independently of this file.

## Building locally

```sh
GOOS=js GOARCH=wasm go build -o engine.wasm ./cmd/wasm
cp "$(go env GOROOT)/lib/wasm/wasm_exec.js" .
```

`cmd/wasm/main.go` is build-tag gated (`//go:build js && wasm`), so it is
invisible to a normal host build/test — `go build ./...` and `go test ./...`
never touch it.

## JS API

The module registers a single global, `globalThis.OpenKakutouEngine`, with
four functions: `newMatch`, `tick`, `resetRound`, `closeMatch`. Every
function takes and returns one JSON-encoded string in a uniform
`{ data, error }` envelope — exactly one field non-`null`, and the function
never throws (a Go panic is recovered at this boundary and reported as
`error` instead of tearing down the whole page's WASM instance). See
[docs/architecture.md](architecture.md#cmdwasm) for each function's exact
request/response shape and
[`.vibe/decisions/011-tick-orchestration-scope-and-wasm-session-design.md`](../.vibe/decisions/011-tick-orchestration-scope-and-wasm-session-design.md)
for why per-match runtime state stays Go-side in a session registry rather
than round-tripping through JSON on every call.

### `.zss` characters

A program in a `newMatch` request carries its `.cns` states as `states` and its
`.zss` files, in load order (`st`, `stN`, then `stcommon`), as `scripts`, each a
`character/zss` `Script` (`blocks[]` with `kind`, `number`, `headerParams`,
`params`, `ret`, `body`). A state number in both `states` and `scripts` resolves
to `states`: to get Ikemen GO's rule that the first file wins, the caller leaves
out of `states` any number an earlier script defines. A fighter whose starting
state is defined only in `scripts` is valid. Scripts are compiled once, at
`newMatch`; a block that does not parse only fails the `tick` that enters it,
with an error naming the block. See
[`.vibe/decisions/024`](../.vibe/decisions/024-zss-in-tick-merged-state-table.md).

`tick` returns, next to `unsupported` (controller types skipped), a parallel
`skippedCalls`: `[2][]string`, one array per side (`[]`, never `null`), the
`.zss` `call` statements that did nothing this tick because the function is
undefined or the argument or return count is wrong (Ikemen GO logs them and
runs on). It is a per-tick log like `sounds`: a skipped response loses it.

### Sound events

Each entry of `tick`'s `sounds` (one array per side) is one `PlaySnd`:
`{ group, sample, common, channel, lowPriority }`. `common` is `true` when
the value had the `F` prefix (`F5, 0`): the sample is read from the common
sound file (Ikemen GO's fight.def `common.snd`), not from the character's
own `.snd`; no prefix and the `S` prefix both read the character's sounds.
`channel` is the `channel` parameter, `-1` when absent: a sound on a channel
`>= 0` stops the fighter's sound still playing on that channel, unless
`lowPriority` is set, in which case the new sound is dropped while the
channel is busy (Ikemen GO `SoundChannels.Request`). An `M` prefixed value
plays nothing, as in Ikemen GO at commit `54d4148a`, and records no event.

### Controller events

Each entry of `tick`'s `events` (one array per side) is a visual or feedback
controller the fighter's states ran that tick, for the client to draw:
`{ type, params: [{ name, raw, values }] }`. `type` is one of `PalFX`,
`RemapPal`, `MakeDust`, `GameMakeAnim`, `ForceFeedback`, `Explod` and
`EnvShake` (a `FallEnvShake` reports the hit's `fall.envshake` as an
`EnvShake`). Each parameter keeps its text in `raw`; `values` holds its
comma-separated parts evaluated, or is absent when one does not evaluate (an
`F`-prefixed animation such as `F5000`). Like `sounds`, it is a per-tick log.
A landed or guarded hit adds a `HitSpark` event on the attacker's side:
`anim` is the HitDef's `sparkno` (`guard.sparkno` when guarded) as written —
no prefix is the common `fightfx`, `S` the character's own animations — and
`x`, `y` the spark's world position (Y up). Its `hitsound` / `guardsound` is a
sound event, `common` unless prefixed `S`.

`projectiles` is each side's live projectiles after the tick, always an
array: `id`, `anim` (one of the owner's animations) and `animTime` (ticks
into it), `x`, `y` (world position, Y up) and `facing`.

A fighter's `animations` entry carries `fromOpponent` when it shows its
opponent's animation (a thrown fighter in the thrower's state, after
ChangeAnim2): draw it with the opponent's animations and sprites.

The match `state` carries `pauseTime` and `superTime`, the ticks left of a
Pause and a SuperPause, and `superDarken`: darken the screen while
`superTime` runs.

`helpers` is each player's helpers after the tick, always an array: `id`
(the helper id), `stateNo`, `anim` (one of the player's animations) and
`animTime`, `x`, `y` (world position, Y up) and `facing`; draw each like a
fighter.

`explods` is each player's live explods after the tick (Explod, as Ikemen
GO keeps them: made by the controller, following the fighter while bound,
moving by their velocity, gone at their removetime or at the end of their
animation), always an array: `id`, `anim` and `animTime`, `common` (the
animation is the common fightfx's, an `F` anim, else the player's), `x`, `y`
(world position, Y up), `facing`, `vflip` (drawn upside down),
`sprPriority` and `onTop` (drawn over everything). The `Explod` event is no
longer reported.

### Example

```js
const result = globalThis.OpenKakutouEngine.newMatch(JSON.stringify(request));
if (result.error) {
  throw new Error(result.error);
}
const { matchId, state, progress, animations } = JSON.parse(result.data);
```

## Verifying a build

`cmd/wasm/smoke.mjs` is a Node.js harness that loads a built module the same
way a browser would (via `wasm_exec.js`) and exercises `newMatch`, `tick`,
`resetRound`, and `closeMatch` — the closest thing to `go test` this file
has, since `syscall/js` code cannot run under the plain Go toolchain:

```sh
node cmd/wasm/smoke.mjs [path/to/engine.wasm]  # defaults to ./engine.wasm
```

## Release pipeline

`.github/workflows/release.yml` runs on every pushed tag matching
`v[0-9]*.[0-9]*.[0-9]*` (e.g. `v1.2.3`). It builds and tests the module
normally first (`go build ./...`, `go test ./...`, `go vet ./...`) —
nothing is published if any of those fail — then builds `engine.wasm` and
copies the matching `wasm_exec.js` (failing the build loudly if that file
isn't found at its expected path, rather than silently publishing a stale
or missing asset), publishing both as assets on that tag's GitHub Release
under stable, predictable names. `wasm_exec.js` is Go-version-specific
glue; the workflow always builds and copies it from the same Go toolchain
install that produced the `.wasm`, so the two published files are
guaranteed to be a matched pair — a consumer should always fetch both from
the same release, never mix versions.
