# engine — Codebase index

## Modules
- [`modules/root.md`](modules/root.md) — entry point; `Tick` ties every sub-package into one usable per-tick match loop
- [`modules/match.md`](modules/match.md) — pure-data match/combat state model: `MatchState`, `FighterState`, `Side`, `Facing`, `Position`, `Velocity`, and the validating `NewMatchState` constructor
- [`modules/evaluator.md`](modules/evaluator.md) — MUGEN CNS trigger/expression parser and evaluator: `Parse`/`Eval`/`Evaluate`, `Context` (wraps `match.FighterState`), `Value`/`Kind`
- [`modules/statemachine.md`](modules/statemachine.md) — StateDef/Controller execution loop: `Step` interprets a fighter's current state's controllers against `evaluator.Context`, applying `ChangeState`/`VarSet` effects in declared order; `ApplyController` is exported so `zssexec` can reuse the same effect logic
- [`modules/zssexec.md`](modules/zssexec.md) — `.zss` Statedef/Function script execution, the `.zss` counterpart to `statemachine`: `Step` parses and runs a script's `if`/`else`/`call`/controller-call statements, reusing `evaluator` for conditions and `statemachine.ApplyController` for controller-shaped statements
- [`modules/input.md`](modules/input.md) — per-tick raw input reading and `.cmd` command matching: `Step` recognizes a character's command-file motions within a buffered time window, producing the set `evaluator.Context.ActiveCommands` consumes
- [`modules/physics.md`](modules/physics.md) — per-tick fighter physics: gravity while airborne, landing on the ground plane, and clamping horizontal position to the current stage's boundaries
- [`modules/hitdetect.md`](modules/hitdetect.md) — per-tick Clsn (collision box) overlap detection: `Detect` resolves an attacker's hit boxes against a defender's hurt boxes, using each fighter's current `character/air` animation frame plus live `Position`/`Facing`, and reports `HitEvent`s — detection only, no damage applied
- [`modules/combat.md`](modules/combat.md) — applies `hitdetect`'s `HitEvent`s to match state: `ApplyHits` subtracts a `HitDef`'s declared damage from the defender's health (floored at 0) and advances a per-defender combo counter, deduping multiple overlapping box pairs into a single landed hit
- [`modules/round.md`](modules/round.md) — round/match flow: `CheckOutcome` decides how a round ends (KO, double KO, timeout with a health tiebreak), `ResetRound` restores fighters for the next round, `Progress` tracks round wins per side across a best-of-N match
- [`modules/wasm.md`](modules/wasm.md) — `cmd/wasm`'s WebAssembly entrypoint: `newMatch`/`tick`/`resetRound` globals, per-match runtime state kept Go-side in a session registry keyed by an opaque match ID, each response additionally reporting per-fighter animation number/timing

## Observed patterns
- TypeScript-free, pure Go; module-scoped packages added incrementally, one per backlog item, in dependency order — the sequencing is now complete, and the root package has grown from a bare skeleton into the orchestration point (`Tick`) over every sub-package
- Tests are co-located with source as `*_test.go`, one behavior per test function, named `Test<Type>_<Condition>_<Expectation>` (mirrors `character`'s convention); tests use the internal `package evaluator`/`package match`/`package statemachine`/`package round`/`package engine` form (not `_test` suffix) since they exercise unexported helpers alongside the public API
- A package exposing a fixed-cardinality collection (here, `MatchState`'s two fighters) pairs a plain, panic-free zero value with a separate validating constructor (`NewMatchState`) rather than only exposing the raw field — centralizing the "exactly N, one per key" invariant in one place instead of pushing it onto every consumer. See `.vibe/decisions/001`.
- When a package needs runtime data that an earlier, already-closed item's data model doesn't carry yet, it introduces its own wrapper type (e.g. `evaluator.Context` embedding `match.FighterState`, `round.Progress` alongside `match.MatchState`) rather than reopening that item's model — keeps closed items' APIs and existing struct-equality comparisons stable. See `.vibe/decisions/002`.
- Fixture-driven tests read realistic MUGEN/Ikemen GO `.cns`/`.air`/`.cmd`-style content from a `testdata/` file rather than hand-writing it inline, mirroring `character/cns`'s own testdata convention — either "styled after real MUGEN idioms" (e.g. `evaluator/testdata/kfm_triggers.cns`, `statemachine/testdata/kfm_idle.cns`, the root package's own `testdata/fighter.cns`/`.air`/`.cmd`) or copied verbatim from a sibling repo's own committed fixture (the root package's `testdata/stage.def`, copied from `stage/cmd/wasm/testdata/sample.def`, the same way `hitdetect/testdata/sample.air` was copied from `character/air/testdata/sample.air`).
- `engine` depends on `character` as a real Go module (first taken on by `statemachine/`), resolved through the standard Go module proxy against `character`'s tagged releases — no local `replace` directive needed.
- `engine` depends on `stage` the same way (first taken on by `physics/`), resolved against `stage`'s tagged releases through the standard Go module proxy.
- Runtime data an earlier item's data model doesn't carry is derived from the fields it already has, not added as a new stored field — `physics.grounded` derives ground/air state from `match.FighterState.Position`/`Velocity` rather than adding a `Grounded` field, the same wrap-rather-than-reopen precedent `evaluator.Context` set (`.vibe/decisions/002`, `physics`'s own `.vibe/decisions/007`).
- A package whose caller must thread evolving state across simulation ticks (`input.State`, `combat.ComboState`, `FighterRuntime`, mirroring `evaluator.Context`) holds no hidden state of its own — every tick's result is an explicit return value the caller passes back into the next call, never a mutable field the package keeps internally.
- `.cmd` command-string direction tokens (`U`/`D`/`B`/`F`/`UB`/`UF`/`DB`/`DF`) are matched case-sensitively, never case-folded: a lowercase letter is a button name instead (`B` is "back", `b` is the kick button), so folding case would silently misparse real command strings that combine both in one step (e.g. `B+b`).
- A package needing a fighter's screen-relative facing to interpret otherwise-raw input (`input.TickInput`'s Left/Right) takes `match.Facing` as an explicit parameter rather than requiring the caller to pre-resolve it — keeping the raw input shape facing-agnostic and centralizing the translation in the one package that actually needs it. See `.vibe/decisions/005`.
- Two packages driving the same kind of effect against overlapping data (`statemachine`'s `.cns` controllers and `zssexec`'s `.zss` controller-call statements) share one exported effect-application function (`statemachine.ApplyController`) rather than each re-implementing `ChangeState`/`VarSet` — a state-existence check is passed in as a `func(int) bool` predicate instead of a concrete `map[int]cns.StateDef`, since the caller's own "does this state exist" data shape differs. See `.vibe/decisions/008`.
- A small interpreter for a real-world DSL that only superficially resembles an existing language (`.zss`, commonly called "Lua-like") is hand-written for the grammar actually observed in real fixtures, rather than embedding a VM for the language it merely resembles — checked against a fixture before committing to either approach, not assumed from the format's name. See `.vibe/decisions/008`.
- Converting a `character`-package local coordinate (a Clsn box's Top/Bottom, which increases downward like screen space) into `match.Position`'s world space (Y increases upward) is a sign flip, not a unit conversion — confirmed against a real `.air` fixture's actual numbers rather than assumed from either package's doc comments, since neither states the other's convention explicitly. See `.vibe/decisions/009`.
- A per-tick hot-path function that runs unconditionally for the whole match duration (`hitdetect.Detect`, and now the root package's own `Tick`) returns/threads `nil`-by-default or fixed-size (`[2]T`) results rather than dynamically appended slices on the common path, and a multi-fighter fan-out is explicitly unrolled into named calls rather than a loop with a closure body — verified with `testing.AllocsPerRun` and `go build -gcflags="-m"` rather than assumed, since `engine` targets a single-threaded `GOOS=js GOARCH=wasm` build where GC work interleaves synchronously with the simulation loop. See `.vibe/decisions/009`, `.vibe/decisions/010`, `.vibe/decisions/011`.
- A fixture too small to live in a package's own `testdata/` copy is instead copied from `character`'s own committed fixture (`hitdetect/testdata/sample.air`, from `character/air/testdata/sample.air`) rather than depending on a sibling checkout at test time or hand-building synthetic `air.Frame` literals — same "copy the real fixture, don't reach across repos at test time" convention several sibling apps (`character-viewer-web`, `stage-viewer-web`) already established for their own WASM-bridge tests.
- A per-tick function that both takes and returns a value it constructs fresh every call (`combat.ApplyHits`'s `match.MatchState`) does so by value, not by pointer, even though the type it wraps (`match.MatchState`) is normally passed by pointer elsewhere in this package (`hitdetect.Detect`'s own read-only `*match.MatchState` parameter) — the two shapes aren't the same problem: a read-only pointer parameter never escapes, while a freshly-built value *returned* past the call frame forces a heap allocation if it's boxed behind a pointer; `physics.Step`'s pre-existing by-value `FighterState` in/out shape already established the pattern this package's own decision record made explicit for `MatchState` too.
- A backlog item's checked acceptance criteria, not its prose Description, are the actual scope contract when the two disagree — `combat`'s own item mentioned a hit driving "an appropriate hit-reaction state" in prose, but no acceptance criterion checked it, so it was left out and the narrower reading was recorded as an explicit decision rather than assumed silently; the root package's own `Tick` applied the same precedent to scope out `.zss` orchestration. See `.vibe/decisions/010`, `.vibe/decisions/011`.
- A frame's resolved-from-animation-data lookup (the root package's own `currentFrame`) treats a non-positive `Frame.Time` as "hold indefinitely", generalizing MUGEN's own `Time == -1` convention so a malformed `Time == 0` can never make the lookup loop forever.
- A stateful WASM module (`cmd/wasm`) keeps per-session runtime state Go-side in a registry keyed by an opaque caller-facing ID, rather than round-tripping it through JSON on every call — an unexported-field-carrying type (`input.State`) would otherwise silently lose data on every round trip. See `.vibe/decisions/011`.
- A per-tick hot-path function that repeatedly parses the same character-loaded, match-lifetime-static string (`evaluator.Evaluate`'s trigger/parameter expressions, `input.Step`'s command `Input` strings, `zssexec.Step`'s Statedef/Function body text) memoizes the parse in a package-level, unsynchronized map keyed by the source string, rather than re-lexing/re-parsing it on every call — safe without a mutex since this engine targets a single-threaded `GOOS=js GOARCH=wasm` build with no goroutines anywhere in the simulation loop.
- A `.zss` script's `call FunctionName();` statement execution (`zssexec.execStmt`) threads an explicit call-depth counter, bounded by `maxCallDepth`, through its own recursive execution rather than trusting the input to terminate — `.zss` bodies are untrusted, mod-authored content where direct or mutual recursion between functions must fail with a descriptive error, not crash the process via unbounded Go-stack recursion.
- A controller-type name recognized by more than one file (`statemachine.ApplyController`'s own dispatch, and the root package's `HitDef` classification in `tick.go`) is declared once as an exported string constant in the package that owns the concept (`statemachine.ControllerTypeChangeState`/`ControllerTypeVarSet`/`ControllerTypeHitDef`) rather than as independently hardcoded string literals in each file that needs to match it.
- A hot-path function accumulating too many scalar/pointer parameters (`tick.Tick`'s `bounds`/`gravity`/`tick`/`comboWindow`) groups them into a small config struct passed by value, not by pointer -- at a few words' worth of fields it stays cheap to copy and off the heap, so a caller building a fresh literal every call (`cmd/wasm`'s `tickJS`) adds no allocation; taking its address instead is flagged as a regression risk directly in the struct's own doc comment, since that would reintroduce the escape this pattern exists to avoid. See `TickConfig` (`.vibe/decisions/009-011`).
- A function scoped to exactly one controller type and one of its parameters (`combat.ApplyHits`'s `HitDef` handling) takes a small purpose-built params type (`DamageParams`) instead of the full `character/cns.Controller`, even though other packages (`statemachine.ApplyController`, `zssexec`'s controller-call handling) keep passing `cns.Controller` whole -- those two genuinely need the whole shape since they dispatch across multiple controller types; a function that never dispatches doesn't inherit that need just because a sibling function does.
- A WASM response field that exposes previously Go-only runtime data (`cmd/wasm`'s `FighterAnimState`/`animations`) is added as a new parallel array, never folded into a type that also serves as a request payload (`match.FighterState`, reused by the `starting` request field) -- keeps the request surface provably unchanged rather than merely undocumented-as-changed. See `.vibe/decisions/012`.
