# `.zss` execution: hand-written interpreter for the actual grammar, reusing `evaluator`/`statemachine` rather than embedding a Lua VM

**Context:** Backlog item 004 left the interpretation strategy open — "most likely by embedding a Lua-compatible interpreter... but the specific interpreter (or a hand-written minimal-compatible subset, if a full Lua implementation proves disproportionate) is deliberately left to be chosen during this item's own implementation." `character/zss` calls the format "Lua-like" but only parses block headers; script bodies are kept as raw, unevaluated text (see that repo's decision 027) — executing them is this item's job.

**Decision:** Inspecting `character/zss`'s own fixture (`zss/testdata/sample.zss`, which the `character` repo's own convention treats as a self-authored, real-world-style corpus stand-in — no committed real-corpus file exists for this format, same as `character`'s other formats) shows the actual body grammar is not valid standard Lua: conditions use C-style braces (`if AnimElem = 1 { ... }`, not Lua's `then ... end`), a single `=` for comparison (not `==`), and controller-call statements shaped exactly like a `.cns` state controller (`changeState{value: 5001;}`, `mapAdd{map:"chain_5a";value:1}`) rather than ordinary Lua function calls. A real Lua VM cannot parse this text as-is; embedding one would still require hand-writing a transpiler from this grammar to real Lua first, which is strictly more work than interpreting it directly. This item therefore adds a small hand-written recursive-descent interpreter (new package `engine/zssexec`) for exactly the observed grammar: `if`/`else` blocks (braces, optionally nested), single-line controller-call statements, and `call FunctionName();` calls to a `Function` block. Condition expressions reuse `engine/evaluator.Evaluate` unchanged — MUGEN's CNS trigger syntax already uses `=` for comparison and `&&`/`||` for boolean combination, the same operators observed in real `.zss` conditions, so no separate expression grammar is needed. Controller-call statements reuse `engine/statemachine`'s existing `cns.Controller` application logic (`ApplyController`, exported from that package for this purpose) instead of re-implementing `ChangeState`/`VarSet` a second time, keeping `.cns`- and `.zss`-driven states behaviorally identical for the controller types both already support.

Scope deliberately left out of this item, each producing a descriptive error rather than a silent no-op or a crash: `let` variable-assignment statements, and `call` to a `Function` block that declares parameters or a return value. Only the state-changing/variable-setting surface `statemachine` already covers is exercised end-to-end here; growing either interpreter's controller-type coverage is expected to happen incrementally via later items, matching the precedent `statemachine.Step`'s own doc comment already set for `.cns`.

**Reason:** Reusing `evaluator`/`statemachine` instead of duplicating their logic keeps the two state-execution paths (`.cns` and `.zss`) provably equivalent wherever their surfaces overlap, and avoids a second, drift-prone implementation of trigger evaluation or `ChangeState`/`VarSet` semantics. Scoping out `let` and parameterized function calls mirrors `statemachine.Step`'s own precedent of implementing a small, real, end-to-end-correct subset now rather than a large partially-correct one.

**Rejected alternatives:**
- *Embed a third-party Lua VM (e.g. `gopher-lua`) and feed it the raw body text*: rejected — the observed grammar is not valid Lua syntax; a VM would reject `if COND { }` and `changeState{value: N;}` outright, so this approach still needs a from-scratch transpiler ahead of the VM, buying nothing over interpreting the grammar directly.
- *Embed a Lua VM and transpile the observed grammar to real Lua first*: rejected — strictly more code and an extra failure surface (the transpiler itself) than a direct interpreter, for a grammar that maps onto `evaluator`/`statemachine`'s existing vocabulary almost one-to-one.
- *Reimplement trigger evaluation and controller application from scratch inside the new package*: rejected — duplicates already-tested logic and risks the two execution paths silently diverging in behavior over time.
