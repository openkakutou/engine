# Module: wasm

**Role:** `cmd/wasm` is the library's WebAssembly entrypoint: thin `syscall/js` glue exposing enough of `engine.Tick`'s simulation loop (see `modules/root.md`) and `round`'s match-flow bookkeeping (see `modules/round.md`) for a mode-* game app to drive a match, without a Go toolchain of its own. It carries no simulation logic of its own — every real behavior lives in the root `engine` package and `engine/round`, unit-tested independently; this file is JSON (de)serialization, a per-match session registry, and the JS-facing call surface.
**Files:** `cmd/wasm/main.go`, `cmd/wasm/smoke.mjs`
**Exports (JS, not Go):**
- `globalThis.OpenKakutouEngine.newMatch(requestJSON)` — `requestJSON` a JSON string with `programs`/`starting` (indexed `[P1, P2]`), `roundTimer`, `bestOf`, `bounds`, `gravity`, `comboWindow`; returns `{ data: '{"matchId","state","progress"}'|null, error: string|null }`
- `globalThis.OpenKakutouEngine.tick(requestJSON)` — `requestJSON` a JSON string with `matchId`, `inputs` (`[2]input.TickInput`); returns `{ data: '{"state","round","progress","matchOver","matchWinner"}'|null, error }`
- `globalThis.OpenKakutouEngine.resetRound(requestJSON)` — `requestJSON` a JSON string with `matchId`, `roundTimer`, `starting`; returns `{ data: '{"state"}'|null, error }`
**Depends on:** `modules/root.md` (`engine.Tick`, `engine.NewFighterRuntime`, `engine.FighterProgram`), `modules/round.md` (`round.NewProgress`, `round.ResetRound`, `round.Progress.RecordRoundResult`/`MatchOutcome`), `modules/match.md`, `modules/input.md`, the external `github.com/openkakutou/stage` module (`stage.StageBoundaries`)

**Design decision:** `main.go` is build-tag gated (`//go:build js && wasm`), invisible to a normal host `go build ./...`/`go test ./...`. Every exposed function is wrapped by a shared `guarded` helper: a panic is `recover()`-ed and reported as `{data: null, error: "..."}` instead of tearing down the module, mirroring `character/cmd/wasm`'s own boundary convention. Per-match runtime state (`engine.FighterRuntime`, `input.State`, `combat.ComboState`) stays Go-side in a `map[int]*session` keyed by an opaque `matchId` `newMatch` returns — never round-tripped through JSON — because `input.State`'s progress-tracking fields are unexported by design and would silently lose in-flight command-recognition data on every JSON round trip. Only already-JSON-tagged summary data (`match.MatchState`, `round.RoundResult`, `round.Progress`) ever crosses the JS boundary. See `.vibe/decisions/011-tick-orchestration-scope-and-wasm-session-design.md`. `smoke.mjs` is a Node.js verification harness (loads the built `.wasm` via `wasm_exec.js`, the same way a browser would) — not a `go test` file, since `syscall/js` code cannot run under the plain Go toolchain — and doubles as a minimal JS usage example.
