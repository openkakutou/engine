# Module: root

**Role:** Entry point of the library. `Version` plus `Tick`, the orchestration function tying every sub-package into one usable per-tick match loop: per fighter, input recognition then CNS state-machine execution then current-frame resolution; then, once for the pair, hit detection; then, per fighter with an active HitDef, damage/combo; then, per fighter, physics; then the round timer counts down by 1 (never below 0; a `RoundTimer` of 0 at the start of a tick is an untimed round, never decremented and never ending on time) and a round-outcome check. Before running physics, `Tick` copies both `StateNo` and `Power` back from each fighter's post-statemachine `evaluator.Context` onto the authoritative `match.FighterState` — a `PowerAdd` controller's effect lives on `Context` during state-machine execution and would otherwise never reach `result.State`/the WASM contract. `TickResult.Sounds [2][]evaluator.SoundEvent` carries each fighter's `statemachine.Result.Sounds` from this tick straight through, indexed by `match.Side` like `Fighters` -- `nil` for a side with no `PlaySnd` this tick (see `.vibe/decisions/017`). `.zss` states run in `Tick` through the same path as `.cns` ones: a `FighterProgram` resolves a state number to a `.cns` `StateDef` (`States`, first) or a `.zss` Statedef block of its compiled script, `-3`/`-2`/`-1` and the current state each running through `statemachine` or `zssexec` as their format says, in one merged table where the first file in load order wins (see `.vibe/decisions/024`). A `.zss` Statedef header enters through `enterState` as a `cns.StateDef` (`zssexec.CompiledScript.Header`). `TickResult.SkippedCalls [2][]string` carries the `.zss` calls skipped this tick (undefined function, wrong argument or return count), next to `Unsupported` (which now also holds `.zss` unsupported controllers), both in per-runtime buffers reused tick after tick (no allocation). `NewFighterRuntime` builds a fresh per-fighter runtime for match start or a round reset. `NewFighterProgram` builds a `FighterProgram` with its animation lookup precomputed once (a `map[int]air.Animation`, first-occurrence-wins on a duplicate `Number`), so `tickFighter`'s per-tick `findAnimation` call is an O(1) map lookup instead of an O(n) scan for the rest of the match; a `FighterProgram` built via a raw struct literal or decoded straight from JSON falls back to the original linear scan. See `.vibe/decisions/013`. `Tick` sets each fighter's `Context.P2` (`snapshotOf`) before it acts: fighter 1 sees fighter 2 as the previous tick left it, fighter 2 sees fighter 1 after its controllers (new state) but before its movement; `applyHitReaction` also sets the attacker's contact counter (1) and target, records the HitDef's fall/velocity/control values on the defender's `GetHit` (`getHitFor`) and puts the defender's move type at H; `tickFighter` counts the contact counter (held in hit pause, reset on state entry unless `movehitpersist`) and the fall time (`stepFall`). See `.vibe/decisions/027`.
**Files:** `version.go`, `tick.go`
**Exports:** `Version` (const string); `Tick(state match.MatchState, programs [2]FighterProgram, runtimes [2]FighterRuntime, inputs [2]input.TickInput, cfg TickConfig) (TickResult, error)`; `TickConfig` (`Bounds *stage.StageBoundaries`, `Gravity float64`, `Tick int`, `ComboWindow int` — passed by value, see the type's own doc comment for why); `FighterProgram`, `FighterRuntime`, `TickResult` (now including `Sounds [2][]evaluator.SoundEvent`); `NewFighterRuntime(fighter match.FighterState, states map[int]cns.StateDef) (FighterRuntime, error)`; `(FighterProgram).NewRuntime(fighter) (FighterRuntime, error)` (the same for a start state defined in either format); `(FighterProgram).WithScripts(scripts []zss.Script) FighterProgram` (compiles the character's `.zss` files, in load order, once); `StateFile{States []cns.StateDef, Script *zss.Script}` and `NewFighterProgramFromFiles(files []StateFile, animations, commands) FighterProgram` (Ikemen GO's first-file-wins merge of `.cns` and `.zss` state files); `LoadFighterProgram(ch *character.Character, defPath string, searchDirs ...string) (FighterProgram, []string, error)` (builds a fighter's table from a loaded character in Ikemen GO's file order, searching the `.def` folder then each searchDir case-insensitively, reading `.zss` from wherever found; the second result lists state-file entries found nowhere, the "cns" constants file included, which `LoadFighterProgram` parses into `FighterProgram.Constants` (`*evaluator.Constants`, `json:"-"`, nil reads Ikemen GO defaults) that `NewRuntime` copies into `Context.Consts` (and the animation index into `Context.Anims`, see `.vibe/decisions/026`), see `.vibe/decisions/025`; shared by `conformance` and `game`, backlog 057); `FighterRuntime.SkippedCalls`, `TickResult.SkippedCalls`; `NewFighterProgram(states map[int]cns.StateDef, animations []air.Animation, commands cmd.CommandFile) FighterProgram`
**Depends on:** `modules/match.md`, `modules/evaluator.md`, `modules/statemachine.md`, `modules/zssexec.md`, `modules/input.md`, `modules/physics.md`, `modules/hitdetect.md`, `modules/combat.md`, `modules/round.md`, `character/air`, `character/cmd`, `character/cns`, `character/zss` (external modules, read-only -- `FighterProgram`'s own fields, `HitDef` controller classification, `.zss` scripts)
**State entry (item 055):** `enterState` follows Ikemen GO's `StateBytecode.init` then `stateDef.Run` (`bytecode.go:17032-17086`, `5444-5512`): types, movehitpersist/hitdefpersist, facep2 (turns toward an opponent behind), velset (`.zss` only), anim (omitted or -1 keeps the animation running), ctrl (omitted keeps it), poweradd (clamped as `PowerAdd`); each field written as an expression (`HeaderExprs`) is evaluated at entry, and an evaluation error fails the tick. Juggle, sprpriority and hitcountpersist are not modelled. `NewRuntime`/`NewFighterRuntime` give control after entry (round start, `system.go:3364`). Known limit: a `.cns` `StateDef` cannot tell an omitted `ctrl` from `ctrl = 0`, nor an omitted `anim` from `anim = 0`, and drops `velset`; its typed values apply (`shortcut:` in `enterState`) until `character` records which header fields are written.
